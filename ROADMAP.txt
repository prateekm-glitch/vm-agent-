PHASE 3: CHAINING PATTERN (Next)
================================================================================

Goal: Decompose VM provisioning into specialized agents that chain together.
      Each agent is an expert in one domain and passes context to the next.
      Matches QForge/ModelForge architecture exactly.

ARCHITECTURE (Gen 3 — Chaining):

  User → Planner Agent
      ↓
  Hardware Inspector Agent
  (checks server health, AIC cards, IOMMU groups, available resources)
      ↓
  VM Installer Agent
  (runs mq_vm.py, navigates Ubuntu installer, handles install errors)
      ↓
  PCI Setup Agent
  (selects IOMMU groups, generates XMLs, attaches cards, handles P2P/ACS)
      ↓
  Post-Setup Agent
  (configures network, runs apt upgrade, verifies VM is reachable)
      ↓
  Result Reporter Agent
  (generates summary, logs, sends notifications)

  Each agent:
  - Has specialized knowledge (agent instructions in agents/*.md files)
  - Receives context from previous agent
  - Passes enriched context to next agent
  - Can loop back if it encounters an error

WHY PHASE 3:
  - More reliable — each agent is an expert in one domain
  - Parallel execution possible (e.g., Hardware Inspector + ISO download)
  - Easier to debug — each agent has clear responsibility
  - Matches QForge/ModelForge architecture exactly

DOMAIN KNOWLEDGE — P2P (PEER-TO-PEER) FOR AIC CARDS IN VMs
================================================================================
Source: Internal email thread "Cloudvbox - Issue with P2P in VM"
        (Ramakrishna Popuri, Ram Charitra Pandit)

KEY FINDING:
"Different IOMMU groups do NOT automatically prevent P2P.
 ACS must be disabled, and the devices should be under the same PCIe switch."

HOW P2P WORKS IN VMs:
1. P2P IS supported in VMs (previously believed unsupported — incorrect)
2. Requirements: ACS disabled + same PCIe switch + IOMMU/ATS support
3. ACS blocking is the most common root cause of P2P failures

HOW TO DISABLE ACS:
  Option A (preferred): sudo qaic-util -a
  Option B (manual): setpci commands on each PCIe switch port

REQUIRED CODE CHANGES:
  1. Create tools/tool_setup_p2p.py (disable ACS, verify PCIe topology)
  2. Add tool_setup_p2p to P2P_PLAN in orchestrator.py
  3. Update tool_list_pci_devices.py to group by PCIe switch for P2P mode
